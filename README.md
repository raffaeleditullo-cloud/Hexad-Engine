## 🏛️ The Sovereign Problem HEXAD Solves

Every developer using AI today (Cursor, Copilot, Claude Code, Devin) experiences the same critical failure mode:
> **The AI hallucinates, rewrites, or mutates core functions that the human author perfected, introduces subtle bugs, and forgets previously resolved errors.**

**HEXAD** solves this fundamentally by establishing a mathematical **Sovereign Invariant Contract**:
1. **The Author's Core Logic is Sacred:** Functions and architecture defined by the human author are locked as `SOVEREIGN_CORE` through semantic AST hashing.
2. **Safe Extensions are Allowed:** The AI is free to add new features, pages, and components, but is strictly barred from altering core author logic.
3. **Anti-Regression Quarantine:** Every resolved bug is permanently recorded as an immune antibody. The AI is physically blocked from re-introducing past failures.

## 🛡️ The Sovereign Invariant Guardian

### 1. Semantic AST Hashing
Upon initial boot, HEXAD scans the repository and generates `.hexad/invariants.json`:
- Hashes AST node topology (control flow, safety assertions, parameters, exceptions).
- Ignores trivial whitespace but detects any attempt to bypass or strip logic.

### 2. Pre-Flight Edit Interception
Whenever an AI proposes a code modification:
- **`APPROVED_SAFE_EXTENSION`**: The edit introduces new functions or extends functionality without mutating author functions.
- **`REJECTED_AUTHOR_VIOLATION`**: The edit alters or deletes an author-defined core function without explicit sovereign authorization.
- **`APPROVED_SOVEREIGN_OVERRIDE`**: The human author explicitly requested that specific refactor in the prompt.
